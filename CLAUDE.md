# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A static GitHub Pages site (served from `docs/`) that shows a group's MTG Commander decks: full card
list with Scryfall art, explained stats, a play guide per deck, and a table life counter. Python 3.13
stdlib only for the build; no Node, no package manager, no bundler. The front-end is plain ES modules.

`ARCHITECTURE.md` is the normative spec (JSON schemas, router, views, Catalan UI copy, design
tokens). `README.md` (Catalan) is the user-facing how-to. Keep both in sync with any change you make;
in particular keep `ARCHITECTURE.md` §6 in sync with `docs/js/i18n/ca.js`.

## Commands

```bash
python3 tools/build_site.py                       # regenerate docs/data/*.json (cwd does not matter)
python3 -m unittest discover -s tests -v          # all tests
python3 -m unittest tests.test_build_site.BuildSiteTests.test_parse_dek_real_totals   # one test
python3 -m http.server -d docs 8000               # local preview at http://localhost:8000/
```

The build prints one `OK <slug> N cards` line per deck and `WARN` lines for cards without roles.
It fails with `card 'Name' not found in cache` if a card is missing from `decks/_cache/cards.json`.
Every build rewrites `generated_at` in `docs/data/index.json`; don't commit that churn alone.

Generated output (`docs/data/`) is committed: after changing anything under `decks/`, rerun the build
and commit `docs/` too. Pages is configured as branch `main`, folder `/docs`.

## Data flow

```
decks/<Owner>/<name>.dek   deckstats XML export; commander = entry with Sideboard="true"
decks/<Owner>/<name>.md    guide (Catalan); optional, same basename as the .dek
decks/roles/<name>.json    card -> role ids; optional
decks/roles.json           role taxonomy (ids/labels English, definitions Catalan; order = display order)
decks/_cache/cards.json    Scryfall cache, name -> card object (committed; required by the build)
decks/owners.json          default owner + per-deck overrides (beats the folder name)
        |
        v  tools/build_site.py (single importable module)
docs/data/index.json                one entry per deck + owners list
docs/data/decks/<slug>.json         cards (with Scryfall image URLs), stats, guide HTML
events/<folder>/event.json          event metadata (date, place, set code, languages, video)
events/<folder>/{event,set}.<lang>.md   event page + optional set guide, one per language
decks/_cache/sets/<code>.json       full card list of a set (Scryfall search dump) for event guides
docs/data/events/{index,<slug>}.json    generated by the same build
        |
        v  docs/js/app.js (hash router) -> views/{home,deck,guide,events,life}.js
```

Owner resolution: `owners.json` entry > folder name > `owners.json` default. Folders `_cache`, `roles`,
`es`, `img` are reserved and never treated as owners. `decks/es/` holds the original Spanish guides as an
archive: the build does not read them; do not delete or translate them.

Build pipeline per deck: `parse_dek` -> `card_summary` (from cache) -> `parse_md` (own Markdown
subset -> HTML, auto-links card names as `.card-ref`, role aliases as `.role-ref`, converts
`<!-- cards:start -->…<!-- cards:end -->` blocks into galleries) -> `compute_stats` -> JSON.
Slugs come from `slugify(title)`; a collision aborts the build.

Routes: `#/`, `#/deck/<slug>`, `#/deck/<slug>/stats`, `#/deck/<slug>/guia[/<section>]`, `#/vides`
(life counter, self-contained in `views/life.js` + `css/life.css`, state in `localStorage`),
`#/esdeveniments`, `#/esdeveniments/<slug>[/info/<section>]`, `#/esdeveniments/<slug>/edicio[/<section>]`.
All URLs are relative so the site works under a repo subpath.

## Conventions and constraints

- Everything user-facing is Catalan. Card names and MTG jargon (ramp, board wipe, sac outlet, Food…)
  stay in English. All UI strings go through `t()` from `docs/js/i18n/ca.js`. Exception: an event's
  pages are written in the languages its `event.json` lists (the visitor toggles between them), and
  their small chrome dictionary lives in `docs/js/views/events.js`.
- Never copy images into `docs/`: every image URL points at the Scryfall CDN. `decks/img/` and
  `decks/_cache/img/` are gitignored local caches (~1 GB).
- `tools/build_site.py` must stay stdlib-only. Tests import it via `sys.path.insert(0, ROOT/"tools")`
  and run real builds against a temp copy, so they exercise the actual `decks/` data.
- Adding cards to the Scryfall cache: use `POST https://api.scryfall.com/cards/collection` (batches of
  up to 75 names) with `User-Agent` and `Accept` headers, as `decks/make_pdfs.py` does. Scryfall
  rate-limits hard; don't loop over `/cards/named`.
- Galleries (`<!-- cards:start -->…<!-- cards:end -->`) only render inside a `##`/`###` section;
  `parse_md` drops galleries that sit in the intro.
- `Hobbits` (Miquel) intentionally has 108 cards; the 100-card expectations in `ARCHITECTURE.md` §8
  don't apply to it.
- No theme toggle: light/dark follows `prefers-color-scheme` via the tokens in `docs/css/base.css`.

## Legacy scripts in `decks/`

`make_pdfs.py`, `make_pdfs_es.py` (printable proxy PDFs), `make_md_pdfs.py` (guide -> PDF via
headless Chrome) and `add_images.py` (inserts card thumbnails into the `.md` guides) predate the site.
They need `requests`, `Pillow`, `reportlab`, `markdown` and are not part of the build or the tests.
`add_images.py` writes the gallery markers the build later turns into web galleries.
